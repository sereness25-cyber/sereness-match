# Supabase 連携準備

`auth.users` を会員IDの発行元とし、検索に出すプロフィール、本人・年齢確認、いいね、マッチング、メッセージ、ブロックを分けます。プロフィールの検索公開は初期値で無効です。確認状態は非公開スキーマに置き、権限を付与したサーバー側から扱います。

- 会員は自分のプロフィールを作成・編集できます。検索公開されたプロフィールは認証済み会員に表示し、相互のブロックを反映します。
- `send_match_like` は相互いいね成立時にマッチIDを返します。同じ相手への再実行では結果を再利用します。
- `send_match_message` はマッチの参加者であり、送信者の本人・年齢確認が済んでいる場合に送信できます。メッセージ閲覧にも自分の確認完了が必要です。
- `block_match_member` は関連するいいね、マッチング、会話を削除します。これは既存試用版と同じ扱いです。正式運用に進む前に、通報時の証拠保全と保存期間を決めます。解除後は新規のいいねから再開します。

## ローカル検証

Supabaseのローカル開発DBでマイグレーションを適用してから、`psql -v ON_ERROR_STOP=1 -f supabase/tests/match_core.sql` を実行します。テストデータはトランザクション内でロールバックします。ポリシー検証にはローカルDBの管理接続を使います。

アプリ側の認証、プロフィール項目の追加、いいね残数、管理者認証と審査フロー、既読・リアルタイム購読、通報・予約連携は後工程です。SupabaseのURLやキーはこの段階では不要です。

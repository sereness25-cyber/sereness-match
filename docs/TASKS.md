## Phase 1の実装順

1. 最新mainから基盤用レビュー枝を分け、#1のソース変更だけを比較する。仕様ファイルの競合を含むPR単純マージは避け、選択的な移植案を準備する。
2. npm/Vite/TypeScriptとCIを固定し、lint・typecheck・既存テスト・ビルドの正常系を確立する。公開入口への変更を伴わないプレビューを用意する。
3. デモのデータを抽出し、画面・永続化・認証・APIの境界と開発設定を整理する。未実装の制限やUIは機能追加のPRに分ける。
4. スマートフォン幅で6タブ・検索・詳細・いいね・チャット・申込み・プロフィール保存・管理デモの回帰を確認する。生成成果物と設定の分離も検証する。
5. 直後のPhase 2で開発用Supabaseへの接続を優先する。サンプルSQLの権限差分が解決するまで対外公開は保留する。

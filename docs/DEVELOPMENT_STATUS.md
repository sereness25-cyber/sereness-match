## ソースと実行環境

- `main/index.html` にHTML、CSS、バニラJavaScriptを同梱。最大480pxのレイアウトと下部6タブ。外部ライブラリ、ネットワーク通信、ビルド設定、サーバーコードは確認範囲にない。
- デモ会員6名をJavaScript内で定義。いいね、ブロック、チャット、プロフィール、申込み・通報を同一ブラウザの `localStorage` キー `serenessDemo` に保存する。会員間・端末間の同期はない。保存例外は表示されない。
- GitHub Pagesの公開URLは [既存の試作版](https://sereness25-cyber.github.io/sereness-match/)。今回のHTTP GETは200で、取得したHTMLはmainのblobと一致した。管理画面はマイページから開く架空データの画面。認証と審査処理は存在しない。
- ルートの画像はHTMLから未参照。内容や人物は確認していない。公開要否と素材の権利を確認する（S-001）。

## 安全性・技術上の問題

- 現行のデモは認証もサーバー側の権限判定もない。手元のいいね・プロフィール・会話・通報はブラウザで変更でき、共有端末で他者が閲覧できる。実会員データへの転用は避ける。
- 「確認済」は架空表示。プロフィールの年齢入力に下限があっても、年齢や独身の確認にはならない。ブロックはブラウザ内の表示制御で、通報は運営には届かない。
- 画面、表示状態、デモデータと保存処理が単一ファイルに集中。保存失敗とデータ破損の通知・復旧、検索状態の保持、再送制御、権限回帰の自動検証が必要。
- #4の試作は明示設定時だけ起動し、ループバックと架空メールに制限する。ブラウザのsessionStorageにセッションが入るため、本番ではXSS対策、セッション保護・失効・端末ごとの方針をレビューする。セキュリティ全体やGit履歴・公開素材の精査は今後のチェック項目。
